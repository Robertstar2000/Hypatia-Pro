# Agentic Blocker Resolution Protocol

In Project Hypatia's **Human-Mediated Agentic Process (HMAP)**, the AI acts as a vigilant auditor. When an agent (like the *Data Auditor* or *Peer Reviewer*) detects a threat to scientific integrity, it raises a **Blocker**.

This document explains the technical and functional sequence that occurs when a user clicks the **"RESOLVE"** button.

---

## 1. The Detection Phase (Context)

Before resolution can occur, a blocker is generated by an Agentic Workflow (e.g., Step 7 Analysis or Step 9 Peer Review). The AI analyzes the output against specific constraints (e.g., "Data contains null values" or "Conclusion overclaims statistical significance").

The system parses the AI's JSON response and injects it into the experiment state:

```typescript
// config.ts
export interface Blocker {
    id: string;
    severity: 'critical' | 'warning';
    msg: string; // e.g., "Sample size n=5 is insufficient for t-test."
    resolved: boolean; // Defaults to false
}
```

If `severity === 'critical'`, the **"Verify & Continue"** button in the UI is disabled, halting the project to prevent compounding errors.

---

## 2. The Resolution Action (User Intervention)

When the Principal Investigator (User) clicks the **RESOLVE** button in the `BlockerDisplay` component, the following sequence is triggered:

### A. State Immutability & Update
The application retrieves the specific `blockerId` passed by the button click. It performs a non-destructive update to the experiment's state tree.

**Code Logic (`ExperimentWorkspace.tsx`):**
```typescript
const handleResolveBlocker = async (blockerId: string) => {
    // 1. Clone the current step data to ensure immutability
    const stepData = { ...(activeExperiment.stepData || {}) };
    const currentStepData = { ...(stepData[activeStep] || {}) };

    // 2. Map through blockers and toggle the specific target to true
    const blockers = (currentStepData.blockers || []).map(b => 
        b.id === blockerId ? { ...b, resolved: true } : b
    );

    // 3. Reassemble the state object
    stepData[activeStep] = { ...currentStepData, blockers };

    // 4. Commit to IndexedDB
    await updateExperiment({ ...activeExperiment, stepData });
};
```

### B. Database Persistence
The modified Experiment object is immediately sent to `Dexie.js`. The change is persisted to `IndexedDB`. This ensures that if the page is reloaded, the blocker remains "Mitigated" and does not re-appear as an active threat.

---

## 3. Functional Outcomes

Once the resolution is committed to the database, the React state updates, triggering a re-render of the workspace.

### 1. Visual Feedback
*   The Blocker card in the UI fades (opacity reduced).
*   The text receives a strikethrough decoration.
*   The status indicator changes from `BLOCKING ARCHIVAL SYNC` to `MITIGATED`.

### 2. Unlocking the Workflow
The application continuously checks the state of the current step to determine if the user can proceed.

**Validation Logic:**
```typescript
const hasCriticalBlockers = currentStepData.blockers?.some(
    b => b.severity === 'critical' && !b.resolved
);

// The "Verify & Continue" button is disabled if this returns true
<button disabled={... || hasCriticalBlockers}>
```

By setting `resolved: true`, the condition `!b.resolved` becomes false. If no other critical blockers exist, the **"Verify & Continue"** button becomes active (green), allowing the user to advance to the next step.

### 3. Automation Resumption
If the project is in **Automated Mode**, the automation engine—which pauses automatically upon detecting critical blockers—will resume its countdown timer or execution loop once the state is cleared.

---

## 4. Philosophical Note (HMAP)

Crucially, **the AI does not resolve the blocker itself.**

Even if the AI suggests a fix, the *act* of resolution is strictly a human privilege. This adheres to the **Human Sovereignty** pillar of the HMAP framework. Clicking "Resolve" signifies that the human PI has reviewed the issue and either:
1.  Fixed the underlying data/text manually.
2.  Regenerated the output to remove the error.
3.  Determined the AI's concern was a false positive and chose to override it.
